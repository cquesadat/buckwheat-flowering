# Pipeline C — GWAS and marker analysis

This pipeline identifies flowering-related SNP associations, annotates gene/CDS overlaps, fits selected-SNP linear models, and compares exact and LD-supported hits. It produces CSV results, not figures.

## Inputs

Place the supplied files in `data/`: `GWAFFs_imputed.txt`, `SNP_information.txt`, `annotated_h2.gff3`, and `out.emapper.annotations.tsv`. Phenotype BLUEs are read from the sibling folder `../B_Flowering_dynamics_Modelling/BLUEs_BLUPs/`. Supplied analysis results belong in the corresponding `outputs/` subfolders.

## Run

From this directory, run in order:

```bash
bash 1.Run_GWAS.sh
Rscript 2_Aggregate_and_Filter_GWAS.R
Rscript 3_Common_And_Unique_Hits.R
Rscript 4_Annotate_Gene_Overlaps.R
Rscript 4.1_Selected_SNP_Linear_Models.R
Rscript 5_Estimate_LD_Decay.R
Rscript 6_LD_Block_Concordance.R
```

If `outputs/associations/all_Filter_GWAS_results_3PC_combined.csv` is already supplied, steps 1–2 can be skipped. Step 5 can be skipped when `outputs/LD_decay/ld_decay_windows_by_chromosome.csv` is present. The archived outputs are selective: step 4.1 requires `outputs/associations/annotated_marker_trait_associations.csv`, which must first be generated by step 4; step 6 uses the archived combined association table and LD-decay windows directly. The GWAS runner accepts either historical `BLUPs_BLUEs_<trait>.csv` or newly generated `<trait>_BLUEs_BLUPs.csv` filenames for across-year BBCH traits.

## Outputs

- `outputs/associations/` — filtered GWAS associations and gene/CDS matches
- `outputs/marker_effects/` — selected-SNP regressions and rankings
- `outputs/concordance/` — exact and LD-supported hits and supporting LD evidence
- `outputs/LD_decay/` — chromosome-specific LD estimates
- `outputs/GWAS_runs/` — individual GAPIT results when GWAS is run

Software: R with GAPIT, tidyverse, data.table and fs.
